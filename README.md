# speckit-pro

A complete [Spec Kit](https://github.com/github/spec-kit) setup with a stricter standard on top: every project keeps its rules, its product, its architecture and its decisions in files, and nothing counts as done without proof.

## Install into a project

One command, from any machine with Git:

```sh
git clone https://github.com/Soliman-Elhassanein/speckit-pro ~/.speckit-pro && ~/.speckit-pro/install.sh /path/to/project
```

That copies a ready-made Spec Kit installation into the project. It needs no Spec Kit CLI and changes nothing outside the project folder. Then open your coding agent in the project and paste the block from `.specify/speckit-pro/adoption-prompt.md`.

Options:

| Option | Effect |
|---|---|
| `--force` | Overwrite an existing installation's commands, scripts and templates. Specs, code, `constitution.md` and the baseline files are kept. |
| `--with-cli` | Also install the pinned Spec Kit CLI with `uv`. |

To update a machine later: `git -C ~/.speckit-pro pull`.

## What a project gets

| Path in the project | What it is |
|---|---|
| `.agents/skills/speckit-*/` | The ten Spec Kit commands, six of them carrying the standard's rules, plus six baseline commands |
| `.agents/skills/speckit-standard.md` | The standard every command follows |
| `.specify/` | Spec Kit's scripts, templates and hooks, the standard's template sections, and the `speckit-pro` workflow |
| `.specify/extensions/baseline/` | Templates and the check script for the project baseline |
| `.specify/speckit-pro/` | Optional modules and the adoption prompt |

## How it works

Project memory, one home per kind of fact:

```
.specify/memory/
  constitution.md   rules   how we work
  product.md        what    one row per capability, with its state
  architecture.md   how     stack, parts, boundaries, rules
  decisions.md      why     one row per decision, never deleted
specs/NNN/          one change, with its proof
```

Four laws:

1. **One home per fact.** Everything else links to it.
2. **Calculate, do not maintain.** A script derives delivery status from verification evidence and checks IDs, links, pins and code drift.
3. **The agent proposes; you approve.** Only one command edits the baseline, and only after you approve the exact rows.
4. **Process weight follows change size.** A new feature, a bug fix and a small change take different paths.

The full rules are in [speckit-universal-profile.md](speckit-universal-profile.md).

## Maintaining it

After changing `preset/`, `extension/` or `workflow/`, or to move to a newer Spec Kit release (edit the [SPECKIT_VERSION](SPECKIT_VERSION) file first, and add a row to the table below):

```sh
sh scripts/build-template.sh
```

[SPECKIT_VERSION](SPECKIT_VERSION) holds the Spec Kit release this project was last built and tested with. The build script refuses to run with any other version, and `install.sh` copies the number into each project.

| Spec Kit release | Used from | Notes |
|---|---|---|
| 1.1.2 | 2026-10-09 | Current. Preset, extension, installer and both folder layouts verified. |
| 0.13.3.dev0 | 2026-10-08 | First version of the standard and the converge preset. |
